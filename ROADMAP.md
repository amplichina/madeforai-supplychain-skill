# Roadmap

Guiding rule: protocols are earned by real adoption, not declared in advance.

## Now: v0.4.x hosted closed alpha

- Sixteen MCP tools with bilingual AI guidance and explicit pause semantics.
- One centrally operated HTTPS MCP endpoint backed by persistent PostgreSQL.
- Protected Chinese operator workspace for all invited alpha tasks.
- Database readiness checks, production migrations, and remote smoke validation.
- Private bearer-key access while tenant accounts and per-client credentials are still pending.
- A safe pre-confirmation macro for fast evaluation.
- Category sanity heuristics that ask questions but never reject valid tasks.
- Nine phase-1 categories covering corporate identity applications and high-frequency custom goods.
- English user workspace, Chinese operator workspace, PostgreSQL persistence, and local in-memory demo mode.
- Before the first pilot ships, define a minimal Reality Delta record: what the AI originally specified, what the human operator corrected, and a reviewed reason code. Keep it inside the existing task and event model unless real usage proves a new abstraction is needed.
- The milestone that matters: complete one real AI-initiated, human-operated manufacturing order and return physical delivery evidence.

## Next milestone: unlocked by the first real closed loop

- Extract a concise Reality Task interaction specification from the working implementation.
- Publish a real, un-staged 30-second demonstration with physical delivery evidence.
- Grow manufacturing knowledge through reviewed category contributions.
- Add a manually verified real payment channel only after provider, compliance, refund, and webhook requirements are selected.

## Access surfaces: one rule set, three ways in

The MCP server is the surface that exists today. Two more are roadmap items with explicit triggers.

- **AI calls us**: the current MCP server, with 16 tools and shared authorization, state, approval, and evidence rules.
- **Users call us directly**: a standalone product for people who do not use MCP. This unlocks only after the first real closed loop.
- **Supply calls us**: an execution API for factories, traders, and logistics providers. This unlocks only when a second real execution network needs integration.

All future surfaces must reuse the same approval and evidence rules. A new surface must not create a second workflow implementation.

## Category phases

The initial wedge is a buying pattern rather than one product: items that organizations remake repeatedly, that AI can help specify or design, and that still require human manufacturing coordination.

- **Phase 1: corporate identity applications and high-frequency custom goods.** Print collateral, exhibition and retail display, apparel and uniforms, badges, acrylic products, cards, packaging cards, stickers, and small-batch merchandise.
- **Phase 2: products companies sell.** Consumer accessories, printed packaging, apparel trims, small home goods, and higher-volume IP merchandise. Unlocks only after phase-1 evidence shows reusable demand.
- **Phase 3: industrial and flexible manufacturing.** Industrial parts, tooling, machining, and custom equipment components. Unlocks only after the system can support category-specific quality evidence and failure recovery.

A new category remains a knowledge entry plus focused tests, not a new workflow. See `docs/CONTRIBUTING-CATEGORIES.md`.

## v1.0: unlocked when a second reality skill exists

- Explore a broader reality-execution protocol across multiple verticals.
- Build a certified Reality Operator network beyond the founding team.
- Consider a marketplace only after a real operator network exists.

## Non-goals until those triggers are real

- No premature renaming around a single skill.
- No standards document before an independent adopter exists.
- No marketplace before there are operators.
- No execution adapters or routing layer while there is only one execution network.
