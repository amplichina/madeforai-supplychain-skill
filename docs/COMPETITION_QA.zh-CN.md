# MadeForAI 答辩预案

配套 21 页初赛与路演方案。适用于初赛问询、复赛和技术质询。

总原则：只把当前代码中可以现场演示的机制说成现有能力，其余明确标为路线图。被问到未实现能力时，先承认边界，再说明由什么真实需求触发开发。

## 一、数字口径

- 16 个 MCP 工具。
- 48 项自动化测试全部通过，覆盖工具、状态安全、鉴权和网页路由端到端；TypeScript 编译零错误。
- 16 步人审优先标准业务闭环，包含订单草稿确认、报价与风险确认、付款确认三道门槛。
- 9 个一期制造品类，覆盖企业 VI 应用物与高频定制品。
- 当前收入为零。第一单的目标是验证真实闭环，不是包装营收。

数字来源统一回答：源码、测试和 CHANGELOG 都在仓库中，可以逐项复现。

## 二、现场演示

### 8 分钟版

1. 打开用户端，用一句自然语言创建制造需求。
2. 展示知识库返回的工艺路线、风险和追问问题，以及 AI 生成的订单草稿。
3. 用户确认草稿，切换到中文生产端，填写人工报价、币种、交期和风险。
4. 回到用户端，确认当前报价编号和风险快照。
5. 演示两次拒绝：跳过第二道确认时不能创建支付链接；AI 调用方不能自填支付金额。
6. 展示生产、质检、物流、交付状态和 `get_task` 的事件历史。

### 3 分钟版

只演示第 1、2、5 步。最有说服力的不是系统完成一次顺利流程，而是它会拒绝自己的调用者绕过确认。

## 三、AI 协作可信度

### 质询：多个 AI 互相评审，会不会只是集体幻觉？

**30 秒回答：**

这是一个真实风险，所以我们规定：任何评审意见如果不能落成代码、断言、测试或一次明确的材料修订，就不采纳。最终裁判不是模型共识，而是类型检查、自动化测试和可运行路径。

**追问时展开：**

不同模型分别承担实现、审计、战略质疑和材料校准。交叉审计的价值不是“更多模型投票”，而是让审计者逐项对照源码、界面和产品主张，发现“材料强于代码”的偏差。被采纳的意见必须留下可检查的变化；被拒绝的建议也很多，包括过早改名、先做 marketplace 和先做自动下单。评委可以直接拉取仓库、运行测试，并在任一 MCP 客户端复验关键闸门。

### 质询：AI 给自己参与的产品好评，算证言吗？

**30 秒回答：**

单独的好评不算证据。AI 的反馈只回答两件事：作为直接调用方，它能否理解工具；当它试图越过确认门槛时，服务端能否拒绝。安全性仍以源码、测试和真实界面为准。

**追问时展开：**

MadeForAI 的第一层直接用户本来就是 AI Agent，人类用户通过自己的 AI 客户端使用它。因此，AI 对工具描述、暂停语义和错误返回是否清楚的反馈有产品价值。但评价与证明必须分开：模型可以提出体验问题，不能为安全性作证；关键约束必须由服务端状态机和自动化测试证明。评委也可以把仓库接入自己的 Codex、Claude 或其他 MCP 客户端独立验证。

## 四、产品与技术

### 质询：为什么不让 AI 直接下单？

制造订单包含工艺可行性、价格、交期、质量和跨境履约责任。MadeForAI 把 AI 放在结构化和协调位置，把现实承诺留给人类确认。这不是少做功能，而是让 Agent 可以进入有责任的真实业务。

系统不生成图片、不运行 LLM 推理、不保存银行卡信息、不自动向供应商下单。

### 质询：人工核价可能需要一天，Agent 会不会超时或乱调用？

现实执行的时间尺度本来就是小时和天。等待人工侧时，工具响应返回 `agent_should_pause: true` 和双语暂停指令，要求 AI 停止自动工具链、向用户汇报，并稍后调用 `get_task`。

服务端还用统一迁移守卫拒绝非法跳转。同一报价的支付链接重试会复用；操作员改价并由用户接受新报价后，旧链接不会复用；没有质检不能发货，没有物流不能完成。

Webhook 当前没有实现。只有真实任务证明轮询已成为瓶颈后，才会增加事件推送。

### 质询：一期九个品类的知识准不准？

知识库把制造常识结构化为工艺路线、风险、AI 应追问的问题、图稿要求和数量参考。它不替代工厂或操作员作出最终判断。

数量和工艺常识只生成澄清问题，不自动拒单。原因是常识可能不适用于具体订单，而一个问题不会造成不可逆损失。真实验证发生在操作员拿到供应商答复并回填之后。

### 质询：支付链路是真的吗？

不是。当前是明确标注的 mock 支付，用来验证“人工报价、用户确认、付款确认、生产解锁”这些门槛。它不处理资金，也不保存卡号。

真实支付只有在服务商账户、主体合规、退款政策和 Webhook 安全条件明确后才接入。在此之前，试点使用外部人工收款，由授权人员记录确认结果。

## 五、可信与安全

### 质询：Operator 报假价或履约质量差怎么办？

系统有三道门槛：订单草稿确认、报价与风险确认、付款确认。第二道门槛保存用户看到的报价编号、价格快照和风险快照；未确认时支付工具直接拒绝。

支付金额只能由服务端从已接受的报价快照生成，AI 调用方不能填写或修改。样品、生产、质检、物流和交付证据进入事件历史。

当前承诺是可追溯，不是密码学意义上的不可篡改。内容哈希、可信存储、Operator SLA 和争议处理属于后续治理。

### 质询：MIT 开源，大厂复制怎么办？

欢迎复用代码。MCP Server 本来就应该降低接入成本。

长期潜在差异来自四类资产的组合：Agent 侧的执行与暂停策略、现实动作的证据 Schema、执行网络适配能力，以及经过人工审核的履约结果。它们目前都没有形成规模，因此只说“潜在壁垒”，不说已经不可复制。

## 六、商业与格局

### 质询：如果大平台开放百万供应商、真实报价、支付和物流，MadeForAI 还剩什么？

如果 MadeForAI 只是另一个供应商入口，就没有长期价值。它争取的是 Agent 侧的中立执行控制层：统一管理授权、状态、风险和证据，让企业自有工厂、大平台和人类执行者都可以成为执行节点。

大平台未来可以是可接入的现实执行网络，而不是我们必须复制的供应链。当前真正完成的是一套人审优先的授权、状态和证据规则；跨网络路由仍在路线图上。

### 质询：Reality Operator 网络就是护城河吗？

不是。Operator 是冷启动执行者、异常处理者和责任节点，不是终局壁垒。如果订单增长十倍，人力也必须增长十倍，那只是一家采购服务公司。

正确的长期指标是：每单人工时间是否下降，多少异常被转化为规则和测试，系统可以连接多少独立执行网络。当前还没有真实样本，第一批订单就是这些指标的起点。

### 质询：三个入口一个人做得完吗？

做不完，所以每个入口都有触发条件。

- MCP 入口已经存在。
- 面向普通用户的独立产品，首单真实闭环后才启动。
- 面向工厂和物流的执行 API，出现第二个真实执行网络后才启动。

不到触发条件不开工。这些约束写进 ROADMAP，不是答辩现场临时承诺。

### 质询：怎么挣钱？现在收入为零怎么讲？

诚实起点就是收入为零。第一单是验证，不是营收。

短期按单收取人工执行服务费和企业试点集成费；中期探索 Managed MCP、任务调用、私有部署和 ERP 集成；跨网络路由与证据服务只有在真实网络形成后才讨论。

杠杆来自一条原则：每一次人工处理过的异常，都应在人工审核后沉淀为规则、Schema 或测试，让任务增长快于人工投入增长。

## 七、团队与执行

### 质询：一个人如何冷启动执行网络？

第一阶段由创始团队亲自承担 Reality Operator，跑通一个小批量真实任务。第一单会产生供应商沟通、工艺确认、样品证据、交期和物流回传，再整理为可复用的操作标准。

认证网络是首单之后的扩展路径，不是当前规模声明。网络冷启动的答案，是创始人先成为第一个执行节点。

### 质询：当前版本到底完成了什么？

- 16 个 MCP 工具、16 步人审优先流程、9 个一期品类。
- 48 项自动化测试全部通过，TypeScript 编译零错误。
- 英文用户工作区、中文生产执行台和中文自动验收页。
- 可演示 AI 提交需求、人工报价、用户确认报价与风险、mock 付款、生产质检、物流和交付回传。

PostgreSQL、Docker、鉴权和 CORS 已具备部署骨架；mock 付款与脚本化生产反馈只用于本地复现，不代表真实商业运营。

## 八、主动披露审计修复

可以主动讲。它证明的不是项目从未犯错，而是缺口可以转化为服务端约束和自动化测试。

1. 第二道人审从引导文字升级为独立工具和持久化快照。
2. 取消调用方填写支付金额，改为服务端读取已接受的报价快照。
3. 通用状态更新加入迁移表校验，证据状态只能由专用工具写入。
4. 支付链接重试改为幂等复用，同时绑定 `source_quote_id`，避免改价后复用旧链接。
5. 金额和币种必须成对提交，不再隐式默认人民币。
6. 发货必须从 `quality_check` 进入，完成任务前必须已有物流记录。
7. 用户端一键演示、Operator API 和登录保护都有路由级端到端测试。
8. 新增一期品类时，不只补知识库，还补双语图稿、中文生产单和生产端界面测试。

## 九、答辩纪律

- 数字统一：16 个工具、48 项测试、16 步流程、9 个一期品类。
- 不说现有 Webhook、真实支付、自动下单、自动学习知识图谱或不可篡改日志。
- 不把 Reality Operator 网络说成终局护城河。
- 中立路由、执行适配器和执行图谱一律标为路线图。
- 不展示或暗示跨客户原始报价、具体交期和供应商数据。
- 高风险问题先用 30 秒版本回答，评委追问后再展开。
- 谈 AI 协作时主动说明哪些建议被拒绝，证明最终决策依据是代码和真实边界。

## 十、复赛前必须补的证据

复赛材料至少补四张真实截图：

1. AI 客户端中的 MCP 工具调用。
2. 中文生产端填写报价与交期。
3. 用户确认报价编号和风险。
4. `get_task` 返回完整事件历史。

收尾建议：

> MadeForAI 当前要证明的不是 AI 能代替人做制造，而是 AI 可以通过一个可审计、有人负责的接口，把意图送进现实，再把结果带回来。
